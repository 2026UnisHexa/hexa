Hexa(흥얼) 서비스 개요

한 줄로

허밍을 녹음하면 악보로 바꾸고, 코드·반주까지 붙여볼 수 있는 웹 작곡 보조 도구다.

왜 만들었나

악상이 떠올라도 바로 악보로 옮기기 어렵다. 악기 없이도 “음만 흥얼거려 두고”, 나중에 코드를 고르고 장르 느낌만 입혀 미리 들어보게 하려는 목적이다.
완성된 DAW를 대체하려는 서비스가 아니라, 아이디어를 빠르게 잡아내는 쪽에 가깝다.

누가 쓰나

  • 멜로디는 있는데 화성·반주 구성이 막히는 사람
  • 악보 입력보다 입으로 먼저 남기고 싶은 사람
  • 짧은 루프·스케치를 MIDI/MusicXML로 가져가고 싶은 사람

무엇을 할 수 있나

  1. 녹음 — 브라우저에서 허밍을 녹음한다.
  2. 멜로디 인식 — 잡음을 줄이고, Spotify Basic Pitch로 음높이를 잡아 MIDI 노트·오선보로 보여 준다. 짧은 음은 묶고, 조성에 맞게 살짝 보정한다.
  3. 코드 고르기 — 멜로디에 맞춰 코드 진행 후보를 최대 3개 제안한다. 마음에 드는 걸 고르고 미리 들을 수 있다. (제안이 실패하면 기본 진행으로 대체)
  4. 장르 반주 — 팝 / 발라드 / 재즈 프리셋으로 반주를 붙인 뒤 멜로디와 같이 재생한다.
  5. 내보내기 — 원본 멜로디, 또는 코드·장르가 반영된 결과를 MIDI · MusicXML로 받는다.
  6. 등록 · 둘러보기 — 회원가입/로그인 후 작품을 올리고, 마켓·마이페이지에서 목록을 본다. 결제·실제 판매 플로우는 아직 없다. 데모·프로토타입 단계다.

부가로 음성 메모를 텍스트로 옮기거나, 가사를 받아보는 기능도 있다.

대략적인 이용 흐름

홈에서 새로 만들기를 누르면
녹음 → 악보 확인 → 코드 선택 → 장르·미리듣기 → 다운로드 / 마켓 등록
순서로 진행한다.
홈에서 마켓을 둘러보거나, 마이페이지에서 내 작품과 프로필을 볼 수 있다.

구성

구분내용
프론트React + Vite, Vercel
백엔드FastAPI (가입·로그인·음원 메타 등), Render
피치 인식Basic Pitch, 브라우저에서 실행
코드·가사·음성→텍스트OpenAI API (서버에서만 호출, 키는 프론트에 없음)
악보·재생OpenSheetMusicDisplay, Tone.js

피치 인식은 기기 안에서 돌아가고, 코드/가사/받아쓰기는 서버 API를 탄다.

지금 단계에서의 한계

  • 결제·수익 정산 없음
  • 마켓은 컨셉 데모 성격이 큼
  • DAW 수준의 편집·멀티트랙·실시간 협업은 범위 밖
  • 인식 품질은 녹음 환경·허밍 정확도에 따라 들쭉날쭉할 수 있음

정리

Hexa는 “흥얼거림 → 악보 → 코드·반주 스케치 → 파일로 가져가기”까지를 브라우저 한 흐름으로 묶어 둔 서비스다.
작곡을 대신해 주기보다, 입에서 나온 멜로디를 작업 가능한 형태로 빨리 올려 주는 쪽에 초점을 맞췄다.
